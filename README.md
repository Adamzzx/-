# 交易所指南：网站与内容后台

这是第一阶段的可运行基础项目。网站名称暂定，尚未上线。你暂时不需要购买域名、服务器或数据库服务。

## 三个部分分别做什么

- Next.js 网站：访客看到的中文页面、交易所资料和比较工具。
- PostgreSQL 数据库：保存资料、文章、管理员账号和推荐链接。
- Payload CMS：通过网页编辑内容的后台，不需要修改代码。

## 已完成与尚未完成

已完成：中文首页、六家交易所资料页、两家自选比较、注册说明页、已发布评测页、后台管理、草稿访问控制、推荐跳转与最小点击记录。后台支持简中、繁中、英文的数据字段，前台当前只提供简体中文。

六家交易所仅预置名称，费用、优惠、资格和评分没有编造。推荐链接需你在后台填写并核实后启用。

还未完成：正式品牌、多语言前台、固定两两比较 SEO 页面、榜单/指南/专题模板、完整作者与审核权限、广告系统、完整分析报表、邮件服务、线上部署。后台目前所有账号都是可信管理员，只邀请你信任的人。

## 第一次在自己电脑启动

需要 Node.js 24 和 Docker Desktop。打开项目目录中的终端，逐行运行：

```bash
npm ci
npm run setup:local
npm run db:start
npm run seed
npm run dev
```

本地电脑浏览器打开 `http://localhost:3000/zh-cn/` 查看网站，打开 `http://localhost:3000/admin` 进入后台。Codex 云环境中的服务目前仅用于内部验证，不提供可点击的公网预览。

首次进入后台会提示创建管理员：填写你自己的邮箱和密码。这是本站后台账号，与交易所账号无关。不要在聊天中发送密码。

`setup:local` 自动生成随机本地密码和 CMS 密钥，保存在忽略的 `.env` 与 `.env.docker`，不会覆盖已有 `.env`。数据库仅绑定本机，不公开端口。不要提交或分享这两个文件。

`seed` 只补齐缺少的交易所，不覆盖已编辑资料，也不创建管理员或推荐活动。以后启动只需先运行 `npm run db:start`，然后 `npm run dev`。

## 编辑资料与文章

1. 后台打开「交易所资料」，选择交易所，填写简介、费用条件和地区说明。
2. 完成资料来源核验后，选择「已核验」并填写核验日期。
3. 在「内容与评测」创建文章。评测的网址标识例如 `binance-review`，类型选择「评测」，关联交易所，编辑正文。
4. 草稿不公开；发布后可通过 `/zh-cn/reviews/binance-review/` 访问。当前其他文章类型可录入后台，但其专用前台模板尚未实现。

## 添加自己的推荐链接

1. 打开后台「推荐链接管理」。
2. 选择交易所，粘贴自己账号的完整 HTTPS 推荐链接。
3. 填写真实的活动条件，必要时设置开始和结束时间。
4. 核实平台推广规则、资格与目的域名，再勾选「已核实并启用」。

网站上的推荐入口统一使用 `/go/binance/` 等地址。更换合作链接时在后台修改即可，不需要改文章。无效、关闭或过期活动转回注册说明页，不会循环跳转。

为防止恶意跳转，只允许代码中登记的对应交易所官方域名。其他官方域名或区域域名需要另行核验并增加到允许名单，不要绕过检查。点击记录不代表实际注册，不保存 IP、钱包地址或邮箱。

## 检查项目

```bash
npm run typecheck
npm run lint
npm test
npm run build
npm run test:smoke
```

`test:smoke` 在本机 Docker PostgreSQL 中创建并重建专用 `exchange_validation` 测试数据库，测试迁移、后台登录、编辑、文章发布、访问权限及推荐跳转，然后删除它。它不使用开发数据库的内容；不要把真实内容存放在该测试数据库。

## 数据保存与上线准备

Docker 的数据库卷保存本地数据。不要执行 `docker compose down -v`，这会删除数据库。GitHub 保存代码，不保存数据库里的文章或账号。

备份可以在项目目录执行：

```bash
mkdir -p .backups
docker compose exec -T db pg_dump -U postgres -d exchange_dev > .backups/database.sql
```

备份可能包含敏感数据，不要提交或分享。发布云环境时，不要把代码快照当作数据库备份；重要内容应额外导出并验证恢复。

正式上线时使用独立托管 PostgreSQL 和对象存储，设置正式 `SITE_URL`、随机 `PAYLOAD_SECRET` 和受支持的数据库 TLS 配置。在全新的生产数据库运行 `NODE_ENV=production npm run db:migrate`，再运行 `NODE_ENV=production npm run seed`，然后构建和启动。开发环境可同步表结构；生产环境关闭自动同步，只执行审阅过的迁移。

必须先通过受控访问创建管理员，再开放后台。上线前还需完成邮件/密码找回、备份恢复、隐私与法律页面、反滥用与日志策略，以及实际内容核验。当前未配置邮件发送，不应依赖密码找回。
