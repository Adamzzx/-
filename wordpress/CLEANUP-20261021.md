## 已定位并修复的具体遗漏

1. 旧隐私草稿流程 `cg_launch_prepare_page_drafts()` 明确保留所有已有页面，包括默认英文隐私页。因此它不会更新已公开的英文模板。新增针对原页面的正文更新，只接受多项默认模板特征匹配；不以标题、ID 或一处 Suggested text 就覆盖页面。
2. 旧清理器将所有非空未知 meta 都视为人工资料。在安装官方 Rank Math 的隔离环境中，已实际复现 `rank_math_internal_links_processed` 和 WordPress `_wp_old_date` 阻止五个演示对象清理。现将两个已知技术字段保留在备份/回收站中，不再误判为人工资料；真实正文、摘要、费用及其他人工字段仍受到保护。这不是生产后台执行日志，不能据此断言它是线上跳过记录的唯一原因。
3. 后台“上线整改”已改接本轮窄范围流程，停止顺带调用品牌、文章旧链接、图片 alt 和说明页草稿初始化。仅更新五个已确认对象、必要受管入口及已匹配的默认隐私页。
4. 额外 `/home/` 只在真实静态首页配置证实与 `/` 等价时设置 301，并完整保留内部对象。其他依赖不能被当成跳首页理由；闲置的已确认占位对象移回收站，由 WordPress 正常返回真实 404。
5. 清理后记录精确废弃路径，阻止 WordPress 在其真实 404 上进行模糊同名猜测跳转。不覆盖仍公开的对象，不把所有 404 重定向首页。

1. 由有权限者在 Hostinger 为 **degendeer.com** 保存同一时点的完整文件与数据库备份，并确认恢复入口。备份应在公开根目录外保存；文章 XML 不能代替数据库备份。
2. 有 SSH/WP-CLI 时可使用 [backup-before-cleanup.sh](ops/backup-before-cleanup.sh)：传入本站绝对根目录和私有备份父目录。脚本核对正式 home 地址，导出完整 SQL、打包站点文件（排除可再生页面缓存），记录插件和首页绑定并校验 SHA-256。脚本在本会话未对生产执行。
3. 保留现用 1.14.0 插件包与 1.14.1 主题包。本地 `/workspace/private/cleanup-20261021/` 的 SQL/文件备份只属于隔离测试站，不能用于恢复生产网站，不在交付 ZIP 或公开仓库中。

### 应用补丁

1. WordPress → 插件 → 安装插件 → 上传 `exchange-guide-plugin-1.14.2.zip`，替换同名插件。无需更换主题或重新初始化导航。
2. 打开 **网站管理 → 上线整改**，核对五个真实对象及隐私政策预检。若因真实正文或有效依赖被保留，界面会报告原因；不能把“已保存”当成已清理。
3. 确认完整备份存在，执行“备份相关对象并执行本轮清理”。程序先保存相关数据库行与当前主题、自定义插件和 MU 插件文件，再做修改；写入或校验失败即停止。
4. 私有相关快照默认放在 WordPress 根目录的父目录下 `.degendeer-cleanup-backups`，运行目录 0700、文件 0600。若主机权限不允许，应在 `wp-config.php` 定义 `CG_CLEANUP_BACKUP_DIR` 指向**公开根目录之外**、由站点 PHP 用户可写的位置。公开目录内的位置会被拒绝。
5. 对象符合核对条件时移入回收站，受管菜单叶项改为草稿。保留四家资料、内容类型注册、REST、媒体、作者页和正式说明页。回收站禁用时拒绝永久删除。存在真实依赖时保留并逐项报错，不自动全文改写文章或强行删除关联内容。
6. `/home/` 的执行报告记录真实首页模式、首页 ID、文章列表页及模板。实际静态首页对象完整保留并规范其等价别名；有其他依赖则报告待处理。
7. 隐私正文只有多项默认英文模板特征匹配且执行前指纹未变化时才更新。原 ID、标题、slug、公开状态、作者和已填 SEO 保留，自写中文页不会覆盖。
