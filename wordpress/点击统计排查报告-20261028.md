# DegenDeer 推广点击统计排查（2026-10-28）

## 结论与验证边界

已确认旧版后台数字统计的是有效推荐跳转地址收到的请求，并不能直接视为用户按钮点击数。独立环境已复现 HEAD、预取、爬虫标识和重复请求增加累计，以及文章确认入口漏计。截图中的 Binance 45 次原值不应删除或重算。

**当前历史数据不足，无法确定异常点击的具体来源。** 代码只保存累计值，没有逐次时间、来源或身份记录；本次也没有 Hostinger 生产访问日志、生产数据库或百度统计账户权限。无法断言 10 月 28 日增加的 20 多次来自机器人、预取或某位访客。

本次只对公开页面做普通 HTML GET，并在本地专用 WordPress 中测试推广请求。没有请求生产 `/go/`、没有发送生产百度点击事件、没有写入生产数据库或部署文件。Bybit 下架任务仍暂停，四家现有配置和链接均不在本次删除范围。

## 旧版实现与统计范围

原实现来自插件 1.14.3，对应修改前提交 `82c6593`。

| 文件 | 作用 |
| --- | --- |
| `plugin/exchange-guide/exchange-guide.php` | `cg_redirect()` 处理 `/go/{slug}/` 及 `?cg_go=`；唯一 `_cg_clicks` 增量写入点；`cg_meta_box()` 读取数字 |
| `plugin/exchange-guide/registration.php` | `cg_go_url()`、推荐/官方目标选择、短代码注册卡片 |
| `theme/exchange-guide/functions.php` | 首页和主题侧栏的中央跳转链接及卡片 |
| `plugin/exchange-guide/review-affiliate.php` | 地区/条款确认 REST 接口及 `/go/review/{文章ID}/` 签名跳转 |
| `plugin/exchange-guide/baidu-analytics.php`、`assets/baidu-analytics.js` | 单独的百度访问与外链点击事件；不写 WordPress 累计字段 |

普通入口调用链：点击按钮或任意程序请求内部跳转地址 → WordPress `template_redirect` 的 `cg_redirect()` → 检查平台及有效推荐 → 非网站管理员时 SQL 自增该交易所的 `_cg_clicks` → 302 到已保存的目标 → 后台读取该平台 postmeta。

这里没有计数 AJAX 或计数 REST 请求，也没有前端点击与后端各加一次。前端百度监听只向 `_hmt` 发送事件，不调用该 SQL。页面加载不会主动执行这条自增；但是预取或链接检测只要额外请求了有效 `/go/`，就会自增。

文章确认入口调用链：提交地区与条款确认 → `/cg/v1/review-eligibility` 返回短期签名地址 → `/go/review/{ID}/` 验证后 302 并退出。旧版这一路径没有写 `_cg_clicks`，不会经过普通入口的计数逻辑。

45 次是 **Binance 这个交易所对象的累计入口请求**，不是某篇文章、某一个按钮或当天独立点击。首页卡片、主题/文章/比较页内凡实际使用同一个 Binance `/go/` 的链接，共用这个字段；更换推荐网址也不会新建计数器。直接写外部推荐网址的链接会绕过它。专题/比较页是否存在 CTA 取决于实际模板与正文，不能只根据页面类型假设都有按钮。官方回退、失效或未启用的推荐不计入旧字段。

## 证据：发现、未发现与尚未验证

已确认并本地复现：

- 对有效 `/go/` 的普通 GET、HEAD、预取和爬虫标识请求都会计数，无须发生 DOM 点击。
- 同一请求重放两次就加两次，旧版没有事件唯一标识。
- 文章签名确认入口漏掉这一累计计数。
- 原 SQL 自增后未显式清除 postmeta 对象缓存；这是持久对象缓存下的陈旧读风险，不能据此认定当天增加了多余点击。

源码与测试没有发现：

- 打开首页、刷新首页五次、打开交易所专题本身增加计数。
- 同一个推荐请求被多个 PHP 计数 hook 重复执行，或百度脚本再写一次本站累计。
- 初始化、迁移或计划任务另行增加 `_cg_clicks`。
- 已存在单行计数器通过“读取旧值再写回”造成并发丢失：原 SQL 的 `+1` 本身是原子更新。

尚未在生产验证：

- 真实数据库是否存在重复 `_cg_clicks` 行。旧版首次并发初始化的 `add_post_meta(..., unique=true)` 没有数据库唯一索引约束，只能指出潜在风险。
- 生产持久对象缓存、服务器/CDN 缓存和实际预取请求日志。
- 10 月 28 日各次请求的时间、来源、UA、请求头、连续程度，或与其他自动化任务的重合。

公开 HTML 另有具体证据：8 个样本均包含 WordPress 的 conservative prefetch 规则，没有 prerender，且未排除 `/go/*`、`/register/*`。首页四个裸 `/go/` 链接未被该规则排除；抽查文章的对应链接带 `nofollow`，已被规则排除。符合条件的浏览器可能预取首页跳转，旧代码会因此计数。这是可行原因，不是当天的逐次归因证据。详见 `audits/referral-clicks-public-20261028.json`。

## 修复内容与新旧口径

插件升级为 1.14.4，主题保持 1.14.2，不修改目标网址、推荐码、参数、费率、文章内容、导航或跳转方式。

1. `/go/` 继续真实 302，但不再写任何点击计数；普通请求、HEAD、重试、预取、链接检测不能再通过访问这个地址增加数字。
2. 新增独立脚本 `assets/referral-clicks.js`，全局只初始化一次，仅处理可信的原生左键/键盘或中键激活。每个 Event 使用一个随机 UUID，同一 Event 被重复回调不会创建第二次报告，独立再次点击有新的 UUID。
3. 新增 `/cg/v1/referral-click-token`：不计数的短期服务端签名凭据，用于避开页面缓存和客户端时钟问题。页面加载/聚焦可能准备凭据，只有真实点击才发计数 POST。凭据请求不创建点击或日志。
4. `/cg/v1/referral-click` 接收事件 POST，检查同源、请求标识、有效凭据、事件格式、有效推荐、已识别自动请求及预览；服务端验证现有管理员 Cookie，避免 REST 把无 nonce 的管理员误当匿名。文章签名目标重验地区、条款、签名与到期条件，不放宽原限制。
5. 新字段 `_cg_confirmed_clicks` 独立累计，原 `_cg_clicks` 完全保留且停止写入。后台分别显示“旧版入口请求累计”和“新版推广点击累计”，不把旧值 45 悄悄改为零或混算为已确认点击。
6. 事件唯一键存于 Options 表（非 autoload），以 UUID 摘要去重。事件声明、新字段初始化及自增置于同一个 InnoDB 事务与平台行锁中；失败回滚声明，重试不会因半次写入而漏计或多计。提交后清除对应元数据缓存。没有新增数据库表或修改表结构。
7. 保留约 7 天的事件入账时间、平台对象 ID、来源路径和普通/文章确认入口类型。时间是服务器确认记录的时间，按 UTC 时间戳存储，后台按 WordPress 站点时区显示，不是浏览器毫秒级动作时间。不保存完整 IP、UA、访客身份、Cookie、UUID 原文、推荐码、来源查询参数或完整目标网址。管理员在交易所编辑页可查看最近记录；每小时计划任务清除到期记录，不减少累计。WordPress 任务调度延迟时清理可能延后。
8. 精确排除 WordPress 原生预取的 `/go/*`、`/register/*`，保留正常页面的预取功能。

新计数只统计有效且启用的推荐链接；官方默认注册入口仍不计入。两个字段都不是 UV、注册、入金或交易数，也不是百度事件分析报表。新接口的同源检查及短期凭据是访问约束，**不是证明真人的验证码**；能伪装正常浏览器并主动获取凭据的程序仍可能提交新事件。

应区分 UV（按平台规则识别的访客）、PV（页面浏览）、Click（可多次发生的推广激活）。旧版入口请求又是第四种口径。截图中的当天访问明细、某平台累计数及当天人工观察的增量不能直接逐项对应。百度被拦截、日期范围/时区差异、机器人直接请求、预取或多次真实点击均可能造成差异，但本次不能逐次证实。百度账户过滤规则和 WordPress 管理员排除也可能不同：例如某个匿名测试访问被百度过滤时，旧版 `/go/` 仍可能计数；本次没有账户权限核实具体过滤设置。截图里的 IP 或地域也不能单独证明访问者是爬虫。

本站旧计数没有日期字段，无法重建 10 月 28 日明细。若要继续归因，需要 Hostinger 当日 `/go/` 访问日志（时间、方法、状态、UA、Referer；如有 Purpose/Sec-Purpose 更好），并核对服务器、WordPress、百度筛选范围与时区。Baidu 无事件分析权限也不影响本次独立计数修复；本次不引入第二套第三方统计。

## 已知限制与遗留事项

- 生产数据库中的实际 45 次没有被本次读取/修改；45 来自用户截图。线上插件仍可能按旧规则继续计数，只有替换部署后才切换口径。部署时若旧累计已经超过 45，新版也保留部署当时的原值，不会将其回写成截图中的 45。
- 新统计为浏览器激活事件的尽力送达，禁用脚本、阻断本站统计请求、极早关闭/卸载页面、断网或数据存储检查失败时可能漏计；不会为了等待统计而阻塞推广跳转。已预热凭据后的普通同标签及新标签点击应以浏览器测试为准。
- 程序可以伪装普通 UA 或执行真实浏览器交互；`isTrusted`、UA 和同源检查不能百分之百识别人类。已识别的 HeadlessChrome 测试会被排除，普通 UA 的本地验收明确为模拟测试流量，不能据此证明生产访问是真人。
- 近七天明细不包含匿名访客/会话标识，因此能查时间、平台、来源路径和重试去重，不能据此计算独立访客或认定多个事件来自同一人。来源路径是浏览器上报信息，也不是不可伪造的归因证明。
- 没有生产持续对象缓存、服务器配置、Baidu 后台、主机日志或大陆实网权限，相关项未验证。没有执行百度死链、Bing/IndexNow 或 Bybit 下架操作。
